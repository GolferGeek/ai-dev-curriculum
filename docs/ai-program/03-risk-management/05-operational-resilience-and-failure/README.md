# Operational resilience and failure

This node addresses inaccurate output, provider outages, tool and agent errors,
runaway loops, inconsistent state, model changes, attacks, and operational
dependency on AI-assisted workflows.

The company stance should state continuity requirements, fallback constraints,
timeouts, retry and idempotency rules, rollback, recovery, observability,
failure injection, incident escalation, manual alternatives, and recovery
objectives where applicable.

The program agent reports missing recovery, uncontrolled retries, silent
partial failure, absent emergency stops, untested rollback, and monitoring that
cannot detect material failure.
