# Architecture, dependencies, and portability

This node governs shared technical boundaries, supported stacks, dependency
policy, canonical capability sources, and the ability to move organizational
memory and workflows between supported AI harnesses and providers.

The company stance should link architecture standards, supported versions,
dependency and license rules, exception paths, canonical sources, projection
generators, compatibility tests, migration plans, and provider exit paths.

The program agent reports unsupported versions, prohibited dependencies,
direct edits to generated files, untested projections, lock-in without export,
and project conventions presented as shared architecture policy.
