# Phase 03 — Overview

## Today

You will investigate a real codebase, build durable project memory, and feed one verified discovery back into the quality system from Phase 02.

## Learn

- How to turn vague curiosity into evidence-seeking questions
- How to map architecture, data flow, trust boundaries, testing, and ownership
- How Git history exposes actual practice and repairs stale documentation
- How to distinguish fact, inference, preference, policy, and uncertainty
- How to create a codebase-specific investigation skill
- How observations mature into explanations, expectations, and guardrails
- How teams create a self-improving development cycle

## Leave with

- An investigation packet another developer can use
- One corrected or expanded piece of project memory
- One tested custom investigation skill
- One evidence-backed guardrail proposal
- A safe first-change recommendation

## Session arc

| Act | Purpose |
|---|---|
| Why memory matters | Connect Phase 02 guardrails to Phase 03 discovery |
| Frame the questions | Predict, scope, and establish evidence standards |
| Investigate | Run standard tools, then pursue a unique question |
| Build memory | Select, verify, classify, and commit durable knowledge |
| Improve the system | Promote one finding toward a guardrail |
| Return session | Compare discoveries, errors, uncertainty, and next questions |

## The one sentence

> Every investigation should leave the repository easier to understand and harder to damage.
