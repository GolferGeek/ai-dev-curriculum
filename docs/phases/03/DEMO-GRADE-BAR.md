# Demo-grade bar — Phase 03

Phase 03 succeeds when the investigation produces reusable understanding, not when many reports exist.

## Pass

- Questions are specific enough to seek evidence.
- Predictions were recorded before tool output.
- Important claims cite code, configuration, tests, or Git history.
- Facts, inferences, preferences, policies, and uncertainty are distinguished.
- At least one AI conclusion was manually challenged.
- One project-memory artifact was added or corrected.
- Git history was used to confirm or repair the memory.
- One custom investigation skill was created and tested.
- One finding was classified and proposed for promotion.
- The team can name what it would not change yet.

## Fail

- Reports merely restate README content.
- Claims sound confident but have no evidence.
- Tool output is accepted without challenge.
- No repository-specific question is pursued.
- Memory is stored only in chat or a private note.
- A speculative finding becomes a blocking rule without confirmation.
- The lab changes application code before establishing understanding.
- The report hides uncertainty or unresolved contradictions.

## Excellent

- A new developer can use the packet to explain one consequential flow.
- The custom skill finds something the standard toolkit missed.
- Git history materially changes or corrects the system story.
- The promotion proposal balances safety, enforcement cost, and false positives.
- The next investigation question follows naturally from what remains unknown.
