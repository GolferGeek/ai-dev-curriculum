# Run order — Phase 05

## Before the build

1. Review [PREREQUISITES.md](PREREQUISITES.md).
2. Open the capability program and inspect canonical versus generated files.
3. Predict which sources will change, parse poorly, collide, or request risky
   authority.
4. Read the Skills Browser intention and challenge any hard-coded ecosystem
   counts.
5. Produce and review the intention, PRD, and plan artifacts.

## Build

6. Implement source configuration, immutable snapshots, cache, and explicit
   fetch failures.
7. Parse complete skill folders and agent definitions; preserve unknown fields
   rather than discarding them.
8. Normalize stable identity separately from exact revisions.
9. Produce a run-to-run diff: added, changed, removed, unchanged, and failed.
10. Build the source dashboard, catalog, matrix, detail preview, compare view,
    and evaluation worksheet.
11. Make every content, revision, and trust label visible in the UI.

## Evaluate

12. Run a scouting refresh and inspect the diff before looking at popularity.
13. Select one skill, one agent, and one deliberately challenging candidate.
14. Inspect every file and requested authority.
15. Run trigger, non-trigger, collision, safety, and outcome tests on one
    candidate in a sandbox.
16. Record three recommendations. Reject or restrict at least one.
17. Assign the appropriate function group, scope, owner, and re-review trigger.

## Close the bracket

18. Run build, lint, unit/integration tests, structural checks, and browser
    verification.
19. Present one adoption and one rejection to a peer review board.
20. Commit the application and evaluation artifacts on the continuing learner
    branch.

## Stop condition

Do not publish or install a candidate during this phase unless the client has
created a separate, explicit authorization path. “Evaluated” is not
“approved,” and “approved” is not “published.”
