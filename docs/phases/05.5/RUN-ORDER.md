# Run order — Phase 05 Part B

## Understand before change

1. Reopen the Phase 05 application and draw its static-data boundaries.
2. Run its tests and create a verified catalog backup.
3. Read the registry intention; produce and challenge the PRD and plan.
4. Mark the exact points where evaluation, approval, publication, generation,
   installation, and retirement require different authority.

## Migrate

5. Create version-controlled SurrealDB schema, constraints, indexes, and
   migration files.
6. Apply the schema twice to prove idempotence.
7. Import stable capability identities, revisions, files, source snapshots,
   parse failures, and evaluation records.
8. Run parity checks for counts, keys, and hashes.
9. Restore from backup once before proceeding.

## Add governance

10. Add local/team configuration without embedding credentials.
11. Add evaluations, policy decisions, discussions, scopes, restrictions,
    owners, expirations, and use records.
12. Make upstream, reviewed, approved, canonical, generated, and used revisions
    visible.
13. Implement permissions that prevent self-approval and direct
    protected-branch publication.

## Publish and generate

14. Select one Phase 05 candidate and confirm its evidence is still current.
15. Approve one exact revision for project scope.
16. Generate a canonical skill or agent package in the correct functional
    group.
17. Run `npm run ai:generate` and `npm run ai:check`.
18. Open a branch and PR containing the canonical and generated changes.
19. Review the diff as a behavioral dependency, then merge only through the
    authorized training workflow.

## Maintain

20. Refresh the candidate source with a changed upstream revision.
21. Verify the approved revision remains unchanged while the new revision
    enters `re-review-required`.
22. Run the maintenance report.
23. Demonstrate one supersession, restriction, revocation, or retirement.
24. Run build, tests, browser verification, backup, and restore.
25. Present the full lifecycle and commit the work.
