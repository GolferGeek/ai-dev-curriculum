# Demo-grade bar — Phase 02

## Pass

- The learner begins from a reproducible committed application state.
- Scanner output is prioritized and evidence-backed.
- At least one finding is challenged or rejected rather than accepted blindly.
- Approved fixes are scoped and include regression evidence.
- Build, lint/type checks, tests, and browser/runtime verification pass.
- Architecture monitoring identifies drift without silently rewriting design.
- Hardening changes cite the standard they enforce.
- The commit contains only intended work and no secrets.
- Independent PR evaluation identifies residual risk and missing evidence.
- One durable lesson is promoted into a test, rule, skill, or AI-program
  document.

## Fail

- The scanner's confidence is treated as proof.
- The fixer changes unrelated code or deletes failing tests.
- Quality gates pass only because checks were disabled.
- Browser polish substitutes for correctness.
- The same agent authors, approves, and declares high-risk work ready without
  independent review.
- Findings disappear without disposition.
- The learner cannot explain the code that will merge.
