# Phase 07 — AI Program capstone

Phase 07 turns the week's methods into a company-owned operating product: a
folder-backed AI Program, a Governance & GRC application over that record, a
small set of maintained capabilities, and one real change completed under the
new controls.

This is the Day 5 capstone and the eighth primary phase (`00` through `07`). It
does not ask learners to invent law, certify compliance, or finish an
enterprise GRC implementation in one day. It makes the organization's current
stance usable, exposes what is still missing, and establishes how authorized
owners will improve it after the course.

## Learning outcomes

Developers learn to:

- distinguish the durable AI Program from its rebuildable application view;
- adapt the standard eight-category hierarchy without creating competing
  governance silos;
- select Full, Essential, or Light as a view over one canonical program and
  explain which triggers require a broader profile;
- govern AI culture, workforce experience, learning, psychological safety,
  sentiment privacy, and adoption outcomes;
- derive app navigation and folder pages from the canonical filesystem;
- read health findings as record-readiness evidence, not compliance scores;
- answer governance questions with scope, citations, ownership, freshness,
  uncertainty, and next action;
- trace a requirement through risk, control, enforcement, evidence, authority,
  exception, and review;
- prepare a reviewable change without silently activating policy; and
- use the program to govern one low-risk, verified AI-assisted change.

## Product architecture

```text
approved organizational sources and evidence systems
                         ↓
        docs/ai-program/ + decisions + overlays
                         ↓
      validation + trace graph + searchable index
                         ↓
       navigation + dashboards + program advisor
                         ↓
    findings + reviewable proposals + human approval
                         ↓
        merged policy and regenerated capabilities
```

Markdown and approved linked systems remain authoritative. The application is
a projection and operating interface. A database, search index, or model may
help retrieve and synthesize, but none may become an unreviewed policy source.

## Required demonstration

Show the complete loop:

```text
browse folder stance → inspect readiness finding → ask a cited question
→ trace one requirement → prepare a proposal → human review boundary
→ complete one governed change → verify → record next owner and date
```

The demonstration passes when it exposes real unknowns. It fails when course
defaults are relabeled as client policy merely to make the dashboard green.

## Outputs

- Adapted `docs/ai-program/` with owners, approved scope, and explicit gaps.
- An approved or explicitly unassigned program profile with rationale and
  expansion triggers.
- An initial AI-culture stance and privacy-bounded listening decision or named
  owner for the gap.
- Running AI Program Governance & GRC application.
- At least one qualified, cited program answer.
- At least one requirement-to-control trace using approved sources or an
  explicitly fictional teaching record.
- One reviewable proposal that does not alter active policy.
- One bounded application or repository change with risk tier, controls,
  evidence, reviewer, rollback, and result.
- A 30/60/90-day ownership and review handoff.
