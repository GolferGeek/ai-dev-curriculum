# Checklists

Numbered, **do-in-order** lists for teams adopting this curriculum. Each checklist is one outcome — not a phase lesson.

| # | Checklist | Outcome |
|---|-----------|---------|
| **00** | [High-level roadmap](00-high-level.md) | See the full adoption path before diving in |
| **01** | [Your monorepo on GitHub](01-your-monorepo-on-github.md) | Curriculum lives in **your** org repo — your monorepo shell |
| **02** | [GitHub Actions and skills](02-github-actions-and-skills.md) | CI, Pages, guardrails, and headless skills in Actions |
| **03** *(optional)* | [Turbo → Nx](03-turbo-to-nx.md) | Same portfolio + gates; swap orchestrator when outgrowing Turbo |
| **04** | [Deploy apps — Docker + cloud](04-deploy-apps-docker-cloud.md) | One repo; per-app containers to App Service (or equivalent) |

**More checklists** (05, …) — adoption kit week-close, etc.

---

## How to use these

1. Start with **00** — confirm owners and order with your team.
2. Work **01** then **02** before Phase 01 build intensity (SaaS killers need a real repo home).
3. Check boxes in git (commit the filled checklist or a copy under `docs/ai-program/`) so progress is visible — not trapped in one person's notes.
4. Pair **01–02** with the [adoption kit](../../marketing/adoption-kit/README.md) as you fill policy.

**Cohort learners:** do [pre-class setup](../pre-class-setup.md) first, then **01** if you're standing up a team repo (not just cloning locally for class).
